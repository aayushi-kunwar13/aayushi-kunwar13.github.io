Hard graph problems + Top K system design

dsagraphsbfsdfsunion-findhldsystem-designtop-k

Focus areas: DSA (three hard graph problems) and an HLD deep dive.

DSA: graphs

  • Making A Large Island: label each island with an id with DFS/BFS and store its size. Then for every 0, add up the sizes of the distinct neighbouring island ids, plus 1. Using a set of ids stops you counting the same island twice. Watch for the case where the grid is all 1s.
  • Shortest Path in a Grid with Obstacles Elimination: BFS where the state is (row, col, eliminationsLeft), not just the cell. Visiting the same cell with more eliminations left is a different, better state. Shortcut: if k >= m + n - 2, the answer is just the Manhattan distance.
  • Bus Routes: BFS over routes, not stops. Build stop -> routes, start from every route that passes the source, and each BFS level means one more bus. Mark routes as visited so each route is expanded only once.

HLD: Top K (Hello Interview, YouTube)

Watched the Hello Interview deep dive on a Top K system (for example, the top K most-viewed videos over a time window).

  • Requirements: top K by views over fixed windows (hour / day / month / all-time), and a choice between exact and approximate counts, which drives the whole design.
  • Ingestion: view events go to a Kafka stream, partitioned by video id so each counter owns a slice of the keyspace.
  • Counting: stream processors keep per-window counts plus a min-heap of size K per partition. A query merges the partial top-K lists.
  • Windows: count in small time buckets (for example per minute) and roll them up to hours and days. Sliding windows need to subtract buckets that fall out of the window.
  • Scale tricks: a Count-Min Sketch gives approximate counts in bounded memory, and precomputed top-K results are cached so reads are cheap. Keep a batch path for exact recomputation (lambda-style) if exactness matters.
  • Trade-off to articulate: freshness and memory versus accuracy. Say up front which one the interviewer cares about.

Pattern of the day

All three graph problems come down to choosing the right node for the BFS/DFS: island ids instead of cells, (cell, k) instead of cells, routes instead of stops. Top K had the same flavour: picking the right unit (time bucket, partition) is most of the design.
