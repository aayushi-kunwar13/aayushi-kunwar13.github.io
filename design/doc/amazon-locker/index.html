Amazon Locker System

Functional Req

1.Single locker system

1.There can be multiple size locker

2.Package can be assigned of same size locker , and if not present then try for bigger locker (size matching logic)
3.no locker empty reject the drop with a clear reason (e.g., “no locker available”)
4 During drop-off assign a locker and generate a code
5.System generates a unique pickup code when the courier drops
6.During pickup, Customer enters a code and system verify the code matches assigned code

7.Allow max 3 retry attempts for code entry , -> will send a message (“flagged and locked for staff intervention )
8. If passed, Customer pick up the order , and package will be released from the locker
9.Pickup deadline for 3 days , after that remove from the locker - and locker will be again available for new packages

Non-functional

1.Extensible - Locker assignment strategy can be swapple with other logic

2. Scalable - handle more lockers
3.concurrency - handle concurrency if two courier try to drop off packages at the same instant and both get assigned the same locker?
(but to be honest i don’t think in real world its possible ? how can be two courier assigned at once ?
4.code uniqueness - all code generate will be unique - handle by generating random digits

Functional Requirements

  1. Support a single locker station with multiple locker sizes.
  2. On drop-off (given package details — ID, size, customer/order reference), assign a locker of matching size, or next-larger if exact size unavailable.
  3. If no suitable locker is available, reject the drop-off with a clear reason.
  4. Generate a unique pickup code upon successful drop-off.
  5. On pickup, validate the entered code against the package’s assigned code.
  6. Allow a maximum of 3 failed code-entry attempts; on the 3rd failure, lock the package and flag it for staff intervention.
  7. On successful validation, release the package and free the locker.
  8. Enforce a 3-day pickup deadline; if unmet, remove the package and make the locker available again.

Non-Functional Requirements

  1. Extensibility — locker-assignment strategy should be swappable without modifying core logic.
  2. Scalability — support adding more lockers/stations without restructuring core logic.
  3. Concurrency — the system must safely handle concurrent drop-off/pickup requests (e.g., from multiple kiosks or retried API calls) without double-assigning a locker or double-releasing a package.
  4. Code uniqueness — no two active packages should share a pickup code at the same time, including under concurrent code generation.
